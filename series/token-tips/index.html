Part 1 / Foundations

  1. 01

    Cheaper tokens won't fix a vague task

    Consider the whole job: attempts, review, repair, and a useful result.

    Playing loads YouTube. You can also watch on YouTube.

    Read the mini-lesson: Cheaper tokens won't fix a vague task

    Imagine sending prospectors into the mountains with one instruction: find the gold. When they return empty-handed, you negotiate cheaper shovels. Each attempt might cost less, but nobody has a better lead. A coding agent can be just as busy without getting closer to the result you wanted.

    The useful comparison is the whole job, not one request. Include the attempts, your review, and any repair. A slightly longer prompt that names the actual problem can be worth more than a shorter prompt that leaves the agent guessing. Cheaper models still have a place; use one that can meet the task, rather than assuming either a low price or a powerful model will compensate for an unclear job.

    Further reading: VS Code: Optimize AI credit usage

    Try it: Before your next Copilot request, replace a vague phrase such as "improve checkout" with the behavior you want changed and how the agent will know when it is complete. This lets you judge the result, not the confidence of the answer.

  2. 02
    Video coming soon

    Give the agent a clear target

    State what you know, what needs to change, and how you will know it is done.

    Read the mini-lesson: Give the agent a clear target

    "Improve checkout" asks the agent to choose the problem, the scope, and the finish line. A useful task brief makes those choices explicit without prescribing an unproven fix. Start with three things:

    • Evidence: Give a reproduction, an error, or an observed result. Separate what you know from what you suspect.
    • Scope: Say what should change and what must keep working. A likely file is a lead, not proof of the cause.
    • Finish line: Describe observable behavior and the check that would demonstrate it.
    Fix the error when an empty cart reaches checkout.
An empty cart should show a helpful message and submit no order.
Valid carts must still complete checkout.
Add regression coverage for both cases.

    Further reading: VS Code: Write effective prompts

    Try it: Use evidence, scope, and a finish line for one real bug in Copilot Chat. Ask Copilot to restate the success criteria before editing. Then review the changes and run the agreed checks yourself; passing tests are evidence, not a substitute for reviewing the requirement.

  3. 03
    Video coming soon

    What goes into an agent's context?

    Follow prompts, instructions, files, history, and tool results through the agent loop.

    Read the mini-lesson: What goes into an agent's context?

    Your message is only part of what the model receives. VS Code assembles context from sources such as instructions, conversation history, attached files, and tool results. Editor context can also contribute, but its behavior varies by interface and settings. If a file matters, attach it explicitly rather than assuming an open tab supplies the whole file.

    The model does not browse your repository by itself. It can request a tool; the agent runs that tool and supplies the result for a later model request. A search can lead to a file read, which can lead to a test run. Those results become more context. An indexed repository helps locate relevant code; it does not mean the entire repository is sent with every request.

    Further reading: VS Code: Understand context · VS Code: Add context to chat

    Try it: In VS Code Chat, use Add Context to attach a small relevant file. Ask: "Explain how this function handles an empty input. Name the files and symbols you use as evidence. Do not edit code." Follow the references back to the code and check the explanation.

  4. 04
    Video coming soon

    Input, output, and cached tokens

    Understand the different token categories before trying to reduce them.

    Read the mini-lesson: Input, output, and cached tokens

    Tokens are the pieces a model processes, not a count of words or characters. The price of an interaction depends on both the model and the types and amounts of tokens involved. Three useful categories are:

    • Input: Information sent to the model for a request, including instructions, relevant history, files, and tool results, not just the message you typed.
    • Output: What the model generates. For reasoning models, usage can also include thinking tokens, not just the visible answer.
    • Cached input: Eligible repeated prompt content reused by the provider. Reusing a matching prefix can reduce cost and latency, but a cache hit is not guaranteed and is not a saved answer.
    A short question + a large attached log = substantial input.
A short prompt + a long generated rewrite = substantial output.

    Further reading: GitHub: How Copilot usage is billed · VS Code: Inspect token usage and caching

    Try it: In VS Code, hover over the model picker to inspect the token-type rates, then inspect session usage through the context-window control after a small Copilot task. Use the breakdown to choose what to investigate. Do not assume all tokens have one price, cached input is free, or fewer prompt words always mean a cheaper completed task.

  5. 05
    Video coming soon

    More context isn't always better

    Keep relevant evidence in focus rather than filling the window with competing information.

    Read the mini-lesson: More context isn't always better

    A context window is a capacity limit, not a target to fill. An exact error and the code that produced it can be more useful than pages of unrelated logs. Extra material can introduce competing instructions, distract from the task, and consume space without helping the model decide what to do.

    Do not solve that by withholding necessary evidence. Start with the goal, constraints, a reproduction, and useful leads; let the agent inspect related code as needed. Keep the conversation on one task. In long chats, older details may be summarized, so preserve the decisions and checks you still need rather than assuming every early message remains available verbatim.

    Further reading: VS Code: Work effectively with context

    Try it: When a Copilot chat drifts, write a short handoff with the goal, constraints, current failure, relevant files, and useful findings. Use it to start a fresh chat and ask what evidence is still missing before making changes. Keep the old conversation available; a fresh chat is not an automatic transfer of its history.
